# Session record: 2026-08-30

This file records the implementation state and important decisions from the initial build session. Future maintainers and coding agents should read this file together with `readme.md` and `deployment.md` before changing the project.

## Project goal

Build a browser-based live church sermon translation console. Supported speech is streamed to Deepgram for transcription, and confirmed source segments are translated by OpenAI into one to three selected target languages. The app does not store audio or transcripts on the server.

## Current architecture

- npm workspace using Node.js 22, TypeScript, React 19, Vite 8, Fastify 5, and Zod.
- `apps/web`: browser capture, WebSocket client, configurable one-to-three-pane translation console, and floating captions.
- `apps/server`: WebSocket orchestration, Deepgram streaming, segment buffering, and OpenAI translation.
- `packages/contracts`: shared and validated client/server message contracts.
- Production serves `apps/web/dist` from Fastify on one origin.
- Docker Compose runs one application container, a persistent SQLite account volume, and binds port 3000 to `127.0.0.1` for a local HTTPS reverse proxy. There is no Redis.

## Current runtime behavior

- Browser audio chunks use `audio/webm;codecs=opus` with a 250 ms MediaRecorder interval.
- Deepgram uses `nova-3`. Verified fixed source codes are `en-AU`, `en-US`, `en-GB`, `zh-HK`, `zh-CN`, `ja`, `ko-KR`, and `id`; the UI defaults to `en-AU`.
- Deepgram `language=multi` is not used because its current set does not include Chinese, Cantonese, Korean, or Indonesian.
- Deepgram endpointing is 300 ms.
- A confirmed segment flushes at a speech final/punctuation boundary, 7 seconds, or 120 characters.
- Translation requests are serialized to preserve order and return only the session's selected targets in a `translations` map.
- Translation context is limited to 8 segments and about 1,200 characters.
- Inactivity timeout is sent in `session.start`; silence audio chunks and KeepAlive traffic do not reset it.
- A single server instance defaults to 10 isolated active sessions (`MAX_ACTIVE_SESSIONS`, range 1-100). Idle WebSocket handshakes time out after 10 seconds and release their slot.
- Default page font sizes are 18 px. Floating captions default to 26 px.

## Logging decision

High-volume timing events such as `api.deepgram.result.final`, `api.openai.responses.response`, and `queue.translation.completed` are now logged at `debug`, so they are hidden with the default `LOG_LEVEL=info`. Events ending in `.error` remain error logs.

Use `LOG_LEVEL=debug` only while diagnosing latency. API keys and sermon text must never be logged.

## Known limitations and follow-up

- Document Picture-in-Picture requires a current Chromium browser and may be unavailable in embedded browser hosts.
- Browsers require a user confirmation dialog for every system-audio capture session. Choose Entire screen and enable Share system audio.
- A webpage cannot inject translated text into Windows Live Captions; a system-level overlay would require a desktop application such as Tauri or Electron.
- Production microphone and system-audio capture require HTTPS, except on localhost.
- Multi-instance deployments have per-process limits; strict global capacity and resumable sessions require shared coordination such as Redis or an admission service.
- Docker was not available in the original WSL environment, so the image and updated Compose configuration could not be executed there. Validate both on the deployment host.
- This workspace did not contain a `.git` directory at the end of the session; initialize or restore version control before production release.
