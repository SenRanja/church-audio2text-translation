## Completed product work

- Added authenticated operator accounts backed by SQLite, single-terminal login enforcement, admin account management, and live-user indicators.
- The seed admin edits the shared church-default translation prompt.
- Ordinary users can save a persistent account-level custom prompt. Clearing it with **Use church default** returns that account to the shared prompt.
- Prompt changes apply to translation sessions started after saving; an already-running session retains the prompt captured when it started.
- Added per-user source transcript ownership, listing, and downloads. The account menu exposes the latest 14 source transcripts belonging to that user.
- New transcript files are stored under `log/<user-id>/`; compatible legacy root logs are visible only when their `User:` header exactly matches the account.

## Public broadcast captions

- Each operator has an anonymous public URL at `/<username>`.
- Public viewers receive captions over SSE from `/api/public/live/:username` and do not need to log in.
- A viewer can display one or two caption panels. The page defaults to one English panel when there is no saved preference.
- Each panel has a visible language dropdown, independent font-size controls, independent auto-scroll, and a close button when two panels are open.
- In one-panel mode, the panel exposes a `+` button to add a second distinct language.
- The SSE language query and server contract accept one or two unique supported languages. Hidden/closed panels are removed from active language demand, avoiding unnecessary translation work.
- Viewer language choices and font sizes are stored in browser local storage.
- The Source region remains visible while connecting, offline, and live.
- Public Focus view hides the Living Word header and removes outer workspace padding while preserving Source and an Exit focus control.
- Mobile layout was browser-checked at 390 x 844 in one- and two-panel modes with no page or horizontal overflow.

## Translation request behavior

- For every finalized source segment, the server creates the deduplicated union of operator target languages and currently active public-viewer languages.
- That union is sent in one OpenAI Responses API call. The complete result is published to viewers, while the operator receives only the operator-selected subset.
- Viewer language demand is removed when the corresponding SSE connection closes.
- Historical segments are not retranslated when a viewer selects a newly requested language; that language becomes available from the next caption.
- Rolling source context is limited to eight prior segments and approximately 1,200 characters.
- Scripture references are model-generated text. The UI does not strip references. The prompt asks for inferred references only when identification is highly confident, so short or split live segments may legitimately omit an attribution.

## Operator interface

- The desktop operator page supports up to three independently scrolling translation panels.
- Auto-scroll uses direct `scrollTop = scrollHeight`, followed by animation-frame and font-ready corrections. Smooth scrolling is intentionally disabled because frequent live updates caused it to lag behind.
- Flex scroll containers use `min-height: 0`; this is necessary for each translation panel to develop an independent scroll range.
- The Source region has reserved space and scrolls internally instead of overlapping translations.
- Operator Focus view hides the Living Word header and audio-capture deck so translations occupy the viewport. Pause/resume, stop, status, and Show controls remain available while focused.
- The public URL action is labeled **Copy broadcast link**, including on mobile.

## Prompt persistence semantics

- `app_settings.default_prompt` stores the church default.
- `users.custom_prompt` stores each ordinary user's persistent override.
- An empty ordinary-user custom prompt means use the church default.
- The seed admin always reads and edits the church default, not a legacy user override.
- The old `sessions.custom_prompt` column remains for database compatibility but is no longer the source of ordinary-user prompt persistence.

## WSL runtime requirement

This repository must be run with Linux Node and npm inside WSL. Windows `npm.cmd` cannot use the WSL UNC working directory and fails by looking for `C:\Windows\package.json`.

Use:

```bash
cd ~/code/churchTranslation
export PATH="$HOME/.local/share/node-v22/bin:$PATH"
hash -r
npm run build
npm start
```

Expected executables:

```text
/home/jayd/.local/share/node-v22/bin/node
/home/jayd/.local/share/node-v22/bin/npm
```

To make the path persistent, add the export to `~/.bashrc`. Do not run this workspace from Windows CMD or PowerShell.
